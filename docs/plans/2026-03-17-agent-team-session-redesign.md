# Agent Team Session 重新設計

## 背景

原 skill 定位為「多角度討論工具」，使用上有兩個問題：
1. 觸發時機不明確，不知道什麼情況該用 team vs subagent
2. 互動方式不真實——成員各說各話，缺乏真正的協作

## 新定位

**自主任務團隊** — 使用者給任務目標，PM + 專業成員自主協作，完成分析、計畫、實作。使用者是老闆，不需懂技術細節。

## 觸發評估

Claude 自動路由，不問使用者：

| 用 Team | 用 Subagent |
|---|---|
| 需要 2+ 不同專業領域 | 單一領域、範圍明確 |
| 有架構/策略決策 | bug 修復、小改動 |
| 跨前後端/技術與商業 | 執行型任務 |

## 角色設計

**PM（固定必有）：**
- 對老闆說白話，不說技術術語
- 翻譯技術討論 → 「我們決定做 X，因為 Y」
- 把分歧整理成選擇題給老闆
- 最終計畫用白話呈現，等 go/no-go

**專業成員 2–3 人：**
- 依任務自動選擇（技術/商業/UX 等）
- 來源：自建 profiles 或 awesome agents

## 流程

```
1. 使用者給任務目標
2. Claude 自動評估 → team 或 subagent

[Team 路徑]
3. 展示成員名單給老闆確認

4. 成員平行分析
5. 成員彼此讀對方分析 → 自然補充（有感覺就說，沒有就不說）
6. PM 白話摘要進度給老闆

7. 老闆可隨時介入（透過 PM）
   → PM 翻譯 → 團隊調整

8. 計畫完成 → PM 白話報告
   → Approve → 實作評估
   → 打回 → 修正

9. 實作評估（自動）
   → 小範圍 → subagent
   → 跨領域複雜 → team 繼續
```

## 互動原則

- 不強制挑戰，自然補足盲點
- 看到別人想法有靈感 → 說出來
- 有真實分歧 → 自然浮現，PM 整理給老闆
- 技術細節留在成員間，老闆只看 PM 摘要
- **有結論才收工**：產出可行動的計畫或實作成果
